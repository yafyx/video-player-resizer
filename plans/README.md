## Findings considered and rejected

Recorded so they are not re-audited next run:

- **"A document-level `pointermove` listener runs on every page."** Refuted by
  reading the code: the overlay's listeners are registered inside
  `createResizeOverlay`, which is only reached via `ensureOverlay()` inside
  `mount()`, which only runs once a player has been detected. A page with no
  video installs nothing.
- **"React (195 kB) is too heavy for the popup."** Real, but the popup loads on
  click and nobody waits on it; React is the project's chosen stack via
  `@wxt-dev/module-react`. Swapping to Preact would save ~180 kB of a 246 kB
  package for no user-perceptible gain.
- **Dependency vulnerabilities.** Not assessable and not a meaningful risk
  surface: `npm audit` cannot run (bun.lock only, no npm lockfile) and there are
  exactly two runtime dependencies, `react` and `react-dom`.
- **XSS via page-derived colour values in `utils/theme.ts`.** Checked and clean.
  Candidate values pass through `probe.style.color = value`; CSSOM rejects
  anything that is not a single valid colour, and the result is re-serialised
  from `getComputedStyle` before use. There is no sink.
- **TypeScript 5.9 → 7.0.** Available, but nothing forces it: no EOL pressure, no
  blocked ecosystem dependency, and the codebase uses no features near the
  boundary.
- **ESLint.** Deliberately excluded from plan 009. Strict `tsc` already covers
  the error classes this codebase actually produces; adding a flat config plus
  three or four dependencies buys very little here. Revisit with a second
  contributor.
